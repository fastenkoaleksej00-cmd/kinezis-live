# 05 — База данных (Supabase Postgres)

22 миграции (`supabase/migrations/0001…0022`), применяются вручную через SQL Editor.
Подготовленные изменения лежат в `sql/` и **не применялись**.

## Находки

### D1. Нет учёта применённых миграций — P1, S
- **Проблема.** Миграции запускаются копированием в SQL Editor. В базе нигде не записано, какие из них выполнены; уже были случаи ошибки посередине файла (0016, 0021). При переносе на новый проект или восстановлении легко пропустить файл.
- **Решение.** Таблица `public.applied_migrations (name text primary key, applied_at timestamptz default now())` и строка `insert … ('0023_…') on conflict do nothing` в конце каждой новой миграции; позже — Supabase CLI (`supabase db push`), который ведёт учёт сам.
- **Польза.** Видно состояние базы, меньше ошибок при развёртывании.

### D2. Индексы под частые запросы — P2, S
- Готовый файл `sql/D1-indexes.sql`: библиотека и программы (опубликовано и одобрено), лента, посты на проверке, а также индексы для триггеров защиты от спама и выгрузки данных. Безопасно применять в любой момент (`if not exists`).

### D3. Конфиденциальность чатов и профилей — P0
- См. `03-security.md`, S1, файл `sql/S1-trainer-privacy.sql`. Это изменение политик, а не схемы; применить первым из всех SQL.

### D4. Владельцы файлов в хранилище — P1
- См. S2, `sql/S2-storage-owner.sql`.

### D5. Ограничения частоты для жалоб и чата — P1
- См. S3, `sql/S3-rate-limits.sql`.

### D6. Генерация типов схемы — P2, S
- `supabase gen types typescript --project-id mjwyglmyfbnnlerqcknb > lib/supabase/database.types.ts` и типизированный клиент. Убирает 35 ручных приведений типов (см. A4).

### D7. Резервные копии — P1, S (процесс)
- Бесплатный тариф без восстановления на момент времени. Раз в неделю: `supabase db dump -f backup-YYYY-MM-DD.sql` (Supabase CLI, нужен пароль базы) и хранение в приватном облаке владельца. Перед каждой миграцией — то же самое.

### D8. Рост таблиц — P2, информация
- `activity_log`, `reactions`, `messages`, `water_days`, `wellbeing_checkins` растут с каждым активным пользователем. При 10 000 пользователей это сотни тысяч строк — для Postgres нормально при индексах из D2. Лимит бесплатного тарифа — 500 МБ базы; хранилище файлов — 1 ГБ (видео тренеров быстро его съедят, см. план Cloudflare Stream в roadmap).

## Порядок применения SQL (когда владелец разрешит)
1. Резервная копия (D7).
2. `S1-trainer-privacy.sql` → проверка входящих у Юлии и у второго тренера.
3. `S2-storage-owner.sql` → загрузка и замена обложки тренером, админом.
4. `S3-rate-limits.sql` → отправить жалобу и 2–3 сообщения в чат.
5. `D1-indexes.sql`.
