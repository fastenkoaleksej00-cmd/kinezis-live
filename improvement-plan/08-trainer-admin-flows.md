# 08 — Сценарии тренера и администратора (круг 2)

Проверено по коду 2026-10-16. Ничего не изменено.

## Сценарий тренера: «загрузить новое занятие»
1. «+» → «Видео-занятие» → выбор файла → загрузка в Supabase Storage → обложка → публикация → очередь проверки.

### T1. Видео до 50 МБ и без прогресса загрузки — P1, M
- **Проблема.** `WorkoutComposer` отклоняет файлы > 50 МБ (лимит бесплатного Supabase). 20-минутная тренировка с телефона в 1080p — 300–800 МБ, то есть тренер почти никогда не сможет загрузить реальное занятие. Во время загрузки показывается только «загружается», без процента; на мобильном интернете это выглядит как зависание.
- **Решение, ближнее.** Тренерам публиковать длинные занятия на свой YouTube и добавлять ссылкой (уже работает, бесплатно). В интерфейсе загрузки при превышении — подсказка «Загрузите на YouTube как скрытое видео и вставьте ссылку».
- **Решение, правильное.** Cloudflare Stream (≈ $5 за 1000 минут хранения + $1 за 1000 минут просмотра) с прямой загрузкой из браузера по протоколу tus (докачка при обрыве, реальный процент). Адаптер уже предусмотрен в `lib/video/resolve.ts` — один новый `kind: "stream"`.
- **Польза.** Тренеры реально могут публиковать; платный контент можно защищать (YouTube нельзя делать платным).
- **Риск.** Расходы; нужна карта для Cloudflare.

### T2. После одобрения заявки тренер должен перезайти — P2, S
- Роль читается при входе; после одобрения кабинет появляется только после выхода и входа. Решение: на странице заявки при статусе «одобрена» кнопка «Открыть кабинет», которая вызывает `router.refresh()` и `supabase.auth.refreshSession()`.

### T3. Тренер не узнаёт о решении по публикации — P2, S
- Отклонённое занятие помечается «Возвращено» в списке, но уведомления нет. До появления пуш-уведомлений — бейдж с количеством возвращённых на пункте «Тренировки» в кабинете и письмо через SMTP (после S5).

### T4. Статистика тренера — только три числа — P2, M
- «В библиотеке / завершений / лайков». Тренеру полезнее: завершения по каждому занятию за 7/30 дней и удержание по программам (сколько дошли до дня 5). Данные уже есть в `activity_log`; нужна агрегирующая функция без раскрытия личностей.

## Сценарий администратора
### AD1. Нет сводки по платформе — P2, S
- Админ видит очереди, но не видит: сколько новых регистраций за неделю, активных за 7 дней, постов, жалоб. Агрегаты одной функцией `admin_overview()` (только для `is_admin()`), карточки на `/admin`.

### AD2. Нет журнала действий модерации — P1, S
- Скрытие поста, отклонение занятия, приостановка тренера не записываются. По Акту о цифровых услугах ЕС платформа должна объяснять решения о модерации и иметь возможность их показать. Таблица `moderation_log (actor, action, target_type, target_id, note, created_at)` и запись из соответствующих серверных действий. SQL-заготовка: `sql/AD2-moderation-log.sql`.

### AD3. Один админ — единая точка отказа — P2, процесс
- Сейчас админ один (первый аккаунт). Нужен второй админ (резервный аккаунт владельца) с 2FA и описанная процедура передачи прав.
