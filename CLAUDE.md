# KINEZIS LIVE — app

A daily-use wellness platform by the KINEZIS brand: trainer feed, workout library, Face Fitness courses,
skincare, saved items, profile and a future subscription. Sibling of the KINEZIS site in `~/Desktop/webcentre1`
(read-only reference; never modify it).

## Stack
- Next.js 15 (App Router), React 19, TypeScript (strict)
- Tailwind CSS v4 (`@theme` in `app/globals.css`, no tailwind.config). Palette copied from the site:
  petrol `ink` #10242B → icy `ice` #F5F8F8, glow `#8EDCF0`, accent `#2A86B4`. App-only `mint` tones for beauty directions.
  Glass surfaces `.glass` / `.glass-dark`, dark `.section-deep`, cover placeholders `.cover`, `.cover-mint`, `.cover-light`.
- `next-intl` without URL prefixes: cookie `kl_locale`, default `en`, dictionaries in `messages/*.json` (en, uk, de, ru). Add every new key to all four files; a key-parity check script pattern lives in git history of this file's commits.
- `motion` for animation, `lucide-react` for icons, `three` (lazy-loaded only on `/body`). No shadcn/ui.
- Supabase (`@supabase/ssr` + `supabase-js`): auth with email + password, `profiles` with roles user/trainer/admin, per-user tables `favorites`, `watch_progress`, `lesson_progress` (RLS: own rows only). Schema in `supabase/migrations/` (0001 users, 0002 workouts/posts with `is_staff()` policies, 0003 first-user-admin, 0004 courses + skincare, 0005 storage buckets, 0006 plans + trainer profile columns, 0007 meal_plans, 0008 profile/health/settings + `avatars` bucket + `delete_my_account()`, 0009 reactions/comments + views, 0010 chat + realtime publication, 0011 member posts + member-videos bucket + public_profile_extras(), 0012 weekly targets, 0013 storage-level video entitlement, 0014 `breath` activity type, 0015 primary goal + target weight + `water_days`, 0027 `can_read_member_video()` (member videos readable only while the post is visible, plus owner/staff), 0026 `admin_overview()` (aggregate numbers on /admin), 0025 `moderation_log` (admin decisions written by `logModeration()` in `lib/admin/moderationLog.ts`, page `/admin/moderation`), 0024 storage owner-or-admin update/delete on covers and videos, rate limits on reports (10/h) and chat (30/10 min), indexes; 0023 trainer privacy (trainers read only chats addressed to them and those members' profiles; `can_see_conversation()`), 0022 seed of the YouTube channel (29 sessions + programme `yoga-5-days`), 0021 community (topic, post_type, tags, endorsed_by, needs_review, `search` tsvector, rate-limit triggers, `endorse_post()`), 0020 `authors.booking_url`, 0019 shop offers, 0018 shop, 0017 `mind` activity type + `wellbeing_checkins`, 0016 multi-trainer: `is_admin()`, `my_author_id()`, ownership policies, review status, applications, reports, `author_stats()`). Public env in `.env.local` (gitignored); never store the service_role key in the repo.
- Package manager: npm (pnpm cannot lock its store in the sandboxed shell). Fonts: Manrope + Caveat via `next/font`.

## Rules
- Work only inside this folder.
- Server Components by default; `"use client"` only for state, events, motion.
- Named exports. No `any`. 2 spaces.
- Every UI string goes through `messages/*.json`; add the key to all three locales.
- Interface language ≠ content language: videos, posts and courses carry their own `language` field.
- Never invent facts: no made-up videos, lessons, products, ingredients, prices, reviews or medical claims.
  Wording: "prevention", "recovery through movement". Never "diagnosis", "treatment", "medical centre".
- The app must keep working with Supabase unconfigured: stores stay local, auth pages show an honest notice.
- Never estimate calories, heart rate or sleep; Apple Health needs the native app (plan in `docs/HEALTH_INTEGRATION.md`). Notification preferences are stored but nothing is pushed yet; say so in the UI.
- No fake backends: a feature without a real data source shows an honest empty state, never a pretend success.
- Shop (migration 0018 `shop_items`, admin-only writes, public reads of published rows): `/shop` (8 categories trimmed from the owner's list: mats, props, bands, balance, weights, recovery, suspension, accessories), `/shop/[category]`, admin `/admin/shop` (photo → `covers/shop/`). Items link out to the partner/supplier (`rel="sponsored"`); no cart and no payments until a payment provider and legal entity exist. Never invent products or prices: empty states until the admin adds real items. Entry points: Home `ShopWidget` (after the goal), bag icon in the phone `TopBar`, Explore, quick access, and "You will need" on workout pages via `equipmentToCategory`. Home: water is opt-in and the check-in sits at the end (`lib/store/home.ts`, toggles in Quick access → Customise; check-in hides once filled or snoozed for the day). Audio: owner's files live in `public/audio` (source folder `Music/` is gitignored); catalogue `lib/audio/catalog.ts` (nature: rain, sea, wind loop; music: yoga-1…4 playlist; `credit` shown when the source needs attribution; `suggestFor` categories). `AudioProvider` in the (app) layout owns one audio element routed through a Web Audio gain (iOS ignores element.volume), so playback survives navigation; `MiniPlayer` floats above the tab bar; Media Session gives lock-screen controls. `MusicSuggestion` appears on calm-category workout and watch pages (music) and meditations (nature). - Body map markers: `regions[].anchor` is only a hint (side + height). At load `BodyScene` derives two surface anchors per region from the model's own tagged vertices (outermost vertex near the region centre facing +z and −z) and projects whichever faces the camera, so dots stay on the bone under zoom/rotate. Dot buttons are 36 px hit boxes centred on the anchor; the label hangs off the side without moving the dot. Loading: `onProgress` reports real bytes only when the server sends a length (else indeterminate), stages model → regions → finish; `BodyMap` shows a slow note at 20 s, fails with retry at 75 s (`attempt` prop rebuilds the scene). `/models/*` is cached immutable for a year (rename the file to ship a new model). Gotcha: vertex zone tags use `regionIds.indexOf(id)` while markers iterate `regions` (different order); always map via `regionIds.indexOf(r.id)`. Dots closer than 22 px are nudged apart horizontally. A replay script approach (parse GLB in Node, rerun `regionAt` with the same index mapping) verified all 13 anchors on 2026-10-15.
- Body map scene rules: render on demand (`needsRender`), pause when hidden, `touch-action: pan-y` so one-finger vertical swipes scroll the page and horizontal drags rotate, DPR ≤ 1.5 on touch devices, WebGL context loss handled, selection/view persisted in sessionStorage `kl_body_state`.
- Performance (2026-10-15): `UserDataSync` takes `signedIn` from the (app) layout and imports the Supabase browser client lazily after idle, so guests never download it and members get it off the critical path (the ~196 kB raw supabase chunk left the shared layout). Middleware skips `/models`, `/covers` and static media (glb, woff2, mp4…). The body-map frame loop stops when idle: `kick()` wakes it on any change (resize, view, zoom, damping), so an idle map costs no frames. Home reads run in one `Promise.all`; feed avatars are `loading="lazy"`.

Reports: `content_reports` + `ReportButton` on workout/post/trainer pages, admin `/admin/reports` (resolve, resolve+hide, dismiss). `/admin/trainers` toggles verified/status. `/admin/profile` = trainer's own card (`AuthorCardForm`, cover palette from `bannerPresets`). Admin nav is role-aware (`AdminNav role`), trainer lists are scoped by `authorId`, forms hide the author select for trainers (`isAdmin` prop) and `authorFor()` in actions ignores the client value. Workouts carry `equipment`, `body_regions`, `safety`; library filters add `author`, `equipment`, `region`; cards show the trainer name. Courses have `kind` (course | program) and lessons may link a library `workout_id` (video reused); programmes list at `/programs`, Face Fitness shows courses only. Stats: `author_stats()` returns aggregates for the caller's own author.
- Mind & rest (`/mind`, linked from Explore, quick access and the Home check-in card; no new tab): content in `lib/mind/content.ts` (meditations body-scan / breath-awareness with weighted steps scaled to 5–15 min, screen break, evening stretch, evidence notes with real sources: Goyal 2014 mindfulness, Davis 2016 gratitude; breaks and evening routine marked insufficient). `StepTimer` is the shared guided-sequence player (ring, pause, chime, optional `BodySilhouette` highlighting the step's region). Finishing calls `useFinishPractice` → `markHabit()` (localStorage `kl_habits`) + `logMindSession()` (`activity_log.item_type = 'mind'`). Journal: `lib/store/checkins.ts` (`kl_checkins`, four 1–5 scales + gratitude) synced to `wellbeing_checkins` by `UserDataSync`, owner-only. Challenges: `ChallengesBoard` (`kl_challenges` start days; counts habits per local day, water from the water goal; missed days just don't count). Focus sounds: Web Audio noise (rain, waves, deep hum), timer with fade, no files.
- Data export: `GET /api/export` returns the member's own rows (RLS, own session) as a JSON download; button in Settings → Account. Booking: trainers set `booking_url` in their card; the trainer page shows "Book a session" (no in-app scheduling or payments). Shopping list: `ShoppingList` on `/nutrition/[slug]` splits the meal texts into an editable checklist (localStorage `kl_shopping`, copy to clipboard).
- Trainer profiles: `/trainers/[id]` from `authors` (bio, specialties, verified, avatar_src, instagram); `TrainerBadge` only when `verified`. `QuickPostButton` (+) on Home for staff → /admin/posts/new.
- Animations respect `prefers-reduced-motion`. No infinite rotation. Screen transitions: `app/(app)/template.tsx` + `.page-enter` (CSS, 280 ms); active tab indicators slide with motion `layoutId` in BottomNav/SideNav.
