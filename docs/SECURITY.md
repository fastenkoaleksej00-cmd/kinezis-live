# Безопасность KINEZIS LIVE: что проверено 15 октября 2026

## Секреты и репозиторий

- В рабочем дереве и во всей истории git нет секретов: ни service_role-ключа Supabase, ни токенов GitHub, ни приватных ключей. Поиск по шаблонам (`service_role`, `sb_secret`, `github_pat_`, `ghp_`, `sk_live`, `PRIVATE KEY`) нашёл только упоминания слов в документации.
- В git отслеживается только `.env.example` с заглушками. `.env.local` в `.gitignore` с первого коммита.
- В клиентскую сборку попадают только `NEXT_PUBLIC_*` значения: URL проекта и публичный (anon) ключ Supabase, которые и задуманы публичными. Серверных секретов в проекте нет вообще: приложение работает через Supabase с правилами доступа к строкам (RLS), а не через собственный сервер с ключом.
- Токен GitHub, который был вставлен в чат 13 октября, в репозиторий не попал. Его нужно удалить на GitHub и создать новый, если это ещё не сделано.

## Что не проверялось и что остаётся

- Ограничение частоты запросов (rate limiting) для комментариев, сообщений и загрузок: не настроено. Supabase даёт базовую защиту, но спам-защиту стоит добавить до роста аудитории.
- Подтверждение email в Supabase выключено для тестов на localhost. Включить перед запуском.
- Собственный SMTP для писем (встроенная отправка Supabase ограничена).
- Внешний аудит и тест на проникновение не проводились. Эта проверка покрывает собственный код и конфигурацию, не инфраструктуру Supabase и Vercel.
